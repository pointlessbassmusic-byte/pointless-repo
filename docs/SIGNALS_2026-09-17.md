# External signals — sources, first correlations, discipline (2026-09-17)

New package `sportsbot/signals/` (data only — nothing is wired into trading;
strategy changes still require backtest/CLV evidence).

## Source policy (probed from this environment)

| source | verdict |
|---|---|
| NWS `api.weather.gov` | **Adopted.** Free public API intended for programmatic use; point forecasts for the 7 Kalshi settlement stations. |
| Bluesky public search (`app.bsky.feed.searchPosts`) | **Adopted.** Open, unauthenticated endpoint; descriptive User-Agent, ≤3 pages/query, 2s pauses, one polite retry on rate limit. |
| Reddit JSON endpoints | **Rejected.** Refuses datacenter clients (HTML interstitial). We respect the access control rather than evade it. |
| X/Twitter | Not attempted — no free API tier for this use. |

## Signal 1: NWS forecast → weather-arm baseline (accuracy-relevant now)

- `signals/nws.py`: forecast high per station/date, converted to P(YES) with a
  normal error model, whole-degree continuity correction, and **lead-aware
  sigma** (`sigma_for_lead`: 1.8°F ramping ~0.55/day, capped 5.5).
- The snapshot service now records forecasts each cycle **before** market rows
  (`weather_forecasts` table), and the exporter uses only forecasts recorded
  **at or before a market's first (max-lead) snapshot** — never backfilled
  (unit-tested both ways). Existing 168 markets therefore keep climatology
  (`nws_rows: 0` on the historical export — the discipline, not a bug);
  every newly sighted market gets the forecast baseline.

**First live correlation** (84 open weather markets, forecast prob vs market
mid, split by lead):

| bucket | n | Pearson | MAE |
|---|---|---|---|
| next-day+ (the substrate's decision regime) | 42 | **+0.862** | 0.069 |
| same-day (market has intraday info) | 42 | +0.126 | 0.203 |

Reading: at the max-lead decision point the forecast is a strong conventional
baseline — expect it to land **between climatology (Brier 0.193) and the
market (0.052)** once settled cohorts accrue; the martingales will measure
exactly where. Same-day markets are the wrong regime for a forecast error
model, and the split shows the pipeline knows it.

## Signal 2: social chatter (research feed; profitability TBD by evidence)

- `signals/chatter.py` + `sportsbot signals-scan/--report`: per-entity post
  counts and event-vocabulary flags (injury/scratched/walkover/rain-delay…)
  from Bluesky public search, timestamped at collection into
  `data/chatter.sqlite`.
- First live scan: "Dodgers" → 100 posts/24h, **7 injury-flagged**
  (injury×5, injured×4); "Carlos Alcaraz" → 18 posts. Signal exists; whether
  it predicts anything is an open question the harness is built to answer:
  `sportsbot signals-report --events <ingest.csv>` joins only chatter
  collected **before** each event's decision time against market residuals
  (|outcome − market_prob|), Spearman, and refuses to opine under n=30 pairs.

## How this becomes profit (or gets killed)

1. Run `signals-scan` on a cron alongside the paper loop; pairs accrue as
   events resolve after collection.
2. `signals-report` weekly. |ρ| that persists across weeks on growing n is a
   candidate feature; noise gets dropped.
3. Any strategy change still goes through the walk-forward backtest and the
   CLV gate — a story about chatter is not evidence; the report is.
