# Where the slate actually goes

_2026-09-22_

The decision feed recorded why the bot passed on a market, but only for
markets that reached pricing. Everything the scanner dropped first vanished
into a log line. On the live Kalshi slate that was most of the slate, so
"the bot placed no bets" and "the bot never looked" were indistinguishable
from the dashboard. `Scanner.scan_verbose` now returns its drops and the
runner records them, so the funnel is visible end to end.

## Measured on the live slate

272 markets, Kalshi prod, 2026-09-22:

| stage | n | what happened |
|---|---|---|
| discovered | 272 | 86 baseball, 186 tennis, **0 table tennis** |
| dropped before pricing | 186 | every tennis market: the model has no rated entities |
| reached pricing | 86 | all baseball, all matched to rated teams |

Three things this showed that the old feed could not.

### Tennis is 68% of the slate and none of it is priceable

`data/ratings/` has baseball (30 teams) and table tennis (458 players).
There is no `tennis.json`, so `TennisModel` has zero rated entities and the
scanner drops every tennis market. This is the best-developed model in the
repo — surface-blended Elo plus the O'Malley/Markov best-of translation —
and it is currently contributing nothing.

It cannot be fixed from a Claude Code session: the Sackmann CSVs live in
`JeffSackmann/tennis_atp`, and this environment's GitHub access is scoped to
this repository, so every path under that repo returns 404 (the repo README
included — it is not a missing-year problem). `sportsbot fit tennis` has to
run somewhere with open network access, e.g. the Linode host.

### Table tennis has no venue on Kalshi any more

458 rated players, zero markets. The series tickers are not wrong —
`/series/KXTABLETENNISMATCH` returns 200 — the series is dormant:

| series | open | closed | settled | last seen |
|---|---|---|---|---|
| `KXTABLETENNISMATCH` | 0 | 0 | 3 | 2026-07-29 |
| `KXWTABLETENNISMATCH` | 0 | 0 | 0 | never listed |

Since the sim moved to Kalshi (#17), the `table_tennis` sleeve — 10% of the
$100 book — has nothing to trade. Worth knowing before reading a flat line
on that sleeve as a modelling result rather than an empty venue.

### Model uncertainty is not the binding constraint

All 86 baseball predictions came back at uncertainty 0.050 against a 0.20
gate: 0 of 86 rejected there. (The probe that produced this ran the scanner
directly without MLB probable-pitcher context, which the runner does supply
from the Stats API; 0.050 is the floor of `0.03 + 0.02 (pitcher unknown)`
with a full rating history. With pitchers attached it can only go lower.)

So on the current slate the uncertainty gate never fires for baseball, and
for tennis it never gets the chance. An earlier reading attributed 134
passes to uncertainty; those were table tennis, from when the venue still
listed it.

## Why drops are aggregated in the feed

One row per (sport, reason), never one per market. The dashboard renders the
most recent decisions, and a slate where one model is unfit drops a few
hundred markets every cycle — written individually they would evict every
real bet and skip from the feed within a single cycle, breaking the view
this change exists to improve. The count carries the same information.

The group label (`(186 tennis markets)`) is deliberately not a venue ticker:
it stands for a group, so it should not look like a market someone can go
and inspect.

The same fix covers the log: an unfit model warned once per market (186
identical lines for one condition, burying the rest of the cycle) and now
warns once per model per cycle.
