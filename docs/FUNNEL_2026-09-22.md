# Where the slate actually goes

_2026-09-22_

The decision feed recorded why the bot passed on a market, but only for
markets that reached pricing. Everything the scanner dropped first vanished
into a log line. On the live Kalshi slate that was most of the slate, so
"the bot placed no bets" and "the bot never looked" were indistinguishable
from the dashboard. `Scanner.scan_verbose` now returns its drops and the
runner records them, so the funnel is visible end to end.

## Measured on the live slate

272 markets, Kalshi prod, 2026-09-22, before and after the Kalshi tennis
bootstrap (#19) was run on this host:

| stage | before | after |
|---|---|---|
| discovered | 272 | 272 (86 baseball, 186 tennis, **0 table tennis**) |
| dropped before pricing | 186 | 96 |
| reached pricing | 86 | 176 |

Three things this showed that the old feed could not.

### Tennis was 68% of the slate and none of it was priceable

`data/ratings/` had baseball (30 teams) and table tennis (458 players) and
no `tennis.json`, so `TennisModel` had zero rated entities and the scanner
dropped every tennis market — the best-developed model in the repo
(surface-blended Elo plus the O'Malley/Markov best-of translation)
contributing nothing.

The Sackmann CSVs are still unreachable from a Claude Code session: they
live in `JeffSackmann/tennis_atp`, GitHub access here is scoped to this
repository, and every path under that repo returns 404 — the README
included, so it is not a missing-year problem. What unblocked it was #19's
`fit tennis --source kalshi`, which bootstraps from settled Kalshi markets
the way table tennis already did: 1,574 matches, 650 players. Scanning went
from 86 markets to 176.

The 96 that still drop are individual unrated players — two markets each,
since Kalshi lists one market per competitor. That is the conservative
matching rule working as designed, and it is now visible instead of silent.

### Table tennis has no venue on Kalshi any more

458 rated players, zero markets. The series tickers are not wrong —
`/series/KXTABLETENNISMATCH` returns 200 — the series is dormant:

| series | open | closed | settled | last seen |
|---|---|---|---|---|
| `KXTABLETENNISMATCH` | 0 | 0 | 3 | 2026-07-29 |
| `KXWTABLETENNISMATCH` | 0 | 0 | 0 | never listed |

Since the sim moved to Kalshi (#17), the `table_tennis` sleeve — 10% of the
$100 book — has nothing to trade. Worth knowing before reading a flat line
on that sleeve as a modelling result rather than an empty venue.

### Model uncertainty binds for tennis, never for baseball

All 86 baseball predictions came back at uncertainty 0.050 against a 0.20
gate: 0 of 86 rejected. (That probe ran the scanner without MLB
probable-pitcher context, which the runner does supply from the Stats API;
0.050 is the floor of `0.03 + 0.02 (pitcher unknown)` on a full rating
history, so with pitchers attached it only goes lower.)

With tennis rated, the gate bites for the first time: **52 of 176**
predictions exceed 0.20, all thin-history players — the bootstrap covers
Jul 15 to Sep 22, so most players are well short of the matches the model
wants. Expect that to fall as the bootstrap window grows.

An earlier reading attributed 134 passes to uncertainty; those were table
tennis, from when the venue still listed it.

## Why drops are aggregated in the feed

One row per (sport, **category**), never one per market. The dashboard renders the
most recent decisions, and a slate where one model is unfit drops a few
hundred markets every cycle — written individually they would evict every
real bet and skip from the feed within a single cycle, breaking the view
this change exists to improve. The count carries the same information.

Grouping is on a stable low-cardinality category rather than the reason
text, and that distinction was earned rather than designed: the first
version grouped on the reason, which names the player, and re-measuring
after the tennis bootstrap turned 96 drops into ~48 rows — still enough to
crowd the feed. The reasons are not lost; three are named per row and the
rest counted (`96 drops -> 1 row` on the live slate).

The group label (`(96 tennis markets)`) is deliberately not a venue ticker:
it stands for a group, so it should not look like a market someone can go
and inspect.

The same fix covers the log: an unfit model warned once per market (186
identical lines for one condition, burying the rest of the cycle) and now
warns once per model per cycle.
